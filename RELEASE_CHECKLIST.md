# Release checklist

## Required before the first public release

- [x] Core contract is JSON + generated Markdown + quality report.
- [x] HTML, DOCX, PDF, PPTX, and slide adapters are optional and do not gate core completion.
- [x] Multi-agent author/reviewer separation remains explicit.
- [x] Research length, authenticity, and input-readiness loop remains explicit.
- [x] Customer selection preserves 55% market attractiveness / 45% enterprise fit by default and reproducible contributions.
- [x] Profit model is defined as value-capture architecture, not growth or cost management.
- [x] Built-in profit-pattern reference uses original generic families instead of a copied catalogue.
- [x] Original decks, rendered slides, client workspaces, caches, and generated confidential reports are excluded.
- [x] Two existing full cases pass schema validation, deterministic Markdown generation, and 100% content/number/evidence/assumption coverage using the release package.
- [x] Skill folder passes the skill structure validator and release unit tests.
- [x] Repository owner selected and added the Apache License 2.0.
- [x] Pseudonymized Chinese and English examples received privacy, dependency, metadata, and distribution-boundary review before being added.

## Public-release hygiene

- Search the final repository for company/client names and personal paths.
- Confirm examples contain no source URLs, confidential figures, embedded document metadata, comments, or hidden content that should not be public.
- Confirm third-party logos, screenshots, slide masters, diagrams, fonts, and paid research are absent or separately licensed.
- Confirm `git status` contains only intended release files.
- Tag the initial release only after the license and examples are cleared.

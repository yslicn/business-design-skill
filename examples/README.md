## Generation boundary

The expected example workflow is:

1. The **Business Design skill** generates and validates `business_design.json` and `business_design.md`.
2. **Claude Cowork** receives the generated Markdown and creates a presentation-style HTML report.

The HTML is not a native output of this skill. It is an optional downstream presentation created from the skill's Markdown. Every example directory must disclose this boundary prominently so readers do not attribute the HTML design or rendering to the Business Design skill.

Recommended disclosure for each example:

> The business-design content in JSON and Markdown was generated by the Business Design skill. The HTML report was subsequently created by Claude Cowork using the generated Markdown as its source. HTML is an optional presentation layer and is not generated by the Business Design skill itself.

These reports use a pseudonym for the focal company, but their public market facts may still make the underlying case inferable. They should therefore be described as **pseudonymized public-information case studies**, not as irreversibly anonymized data. They contain no client workspace, source JSON, source Markdown, private research cache, personal path, or source-file fingerprint.
